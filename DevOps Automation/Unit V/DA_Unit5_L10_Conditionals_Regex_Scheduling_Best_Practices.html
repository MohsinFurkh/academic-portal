Part A · conditionals

In the shell, truth is an exit status

The foundation

0 means success (true); anything else means failure (false). Note that this is inverted from C and Python, and it is the source of endless confusion.

if command; then … fi
# runs `command`, branches on ITS status

if grep -q ERROR log; then …
if systemctl is-active --quiet nginx; then …
if ! ping -c1 -W2 host >/dev/null; then …

echo $?          # last exit status
a && b            # b only if a succeeded
a || b            # b only if a failed

[ is not syntax — it is a command (/usr/bin/[ still exists). That is why it needs spaces around everything, and why [$x = 1] is "command not found".

[[ ]] — use this in bash

# strings
[[ "$a" == "$b" ]]      # equal
[[ "$a" == a* ]]        # GLOB (unquoted!)
[[ "$a" =~ ^[0-9]+$ ]] # REGEX
[[ -z "$a" ]]           # empty
[[ -n "$a" ]]           # non-empty

# numbers — words, not symbols
[[ "$n" -gt 10 ]]       # or (( n > 10 ))
# -eq -ne -lt -le -gt -ge

# combining
[[ -f "$f" && -r "$f" ]]
[[ "$x" == a || "$x" == b ]]

[[ ]] does no word splitting or globbing on its operands, so an empty variable cannot break the syntax. It is bash-only — with #!/bin/sh you must use [ ].

File tests and case

-e exists      -f regular file
-d directory   -L symlink
-s non-empty   -r -w -x  perms
-nt newer than -ot older than

# case: cleaner than an if-chain
case "$1" in
  --dry-run)  dry=1 ;;
  --force)    force=1 ;;
  -h|--help)  usage ;;
  -*)         die "unknown: $1" ;;
  *)          target="$1" ;;
esac

# arithmetic context
(( retries++ ))
(( retries >= MAX )) && die "gave up"

Careful: (( expr )) returns false when the expression evaluates to 0, so (( count )) under set -e exits the script when count is 0.

Reveal

Only number 6 was correct

  1. [ $name = "admin" ] — unquoted. If $name is empty the test becomes [ = "admin" ]: a syntax error. If it contains a space, too many arguments. → [[ "$name" == "admin" ]].
  2. [ "$count" > 10 ] — the nasty one. > is a redirection, so the shell tests whether "$count" is a non-empty string (almost always true) and creates a file named 10 in the current directory. No error, wrong branch, mystery file. → (( count > 10 )) or [ "$count" -gt 10 ].
  3. [[ "$file" == "*.log" ]] — quoting the pattern disables globbing, so it compares against the literal five characters *.log. → drop the quotes on the right: [[ "$file" == *.log ]].
  4. [ -f $path ] then rm $path — unquoted twice. A path with a space fails the test, or deletes the wrong files. Also: the test-then-act is a race; prefer rm -f -- "$path" and check the status.
  5. [[ "$version" = 1.10 ]] — string comparison, so 1.10 ≠ 1.1 and, if you switch to -lt, 1.10 < 1.9. Version comparison needs sort -V or dpkg --compare-versions.
  6. grep -q ERROR app.log — correct. It branches on a command's exit status, which is the idiomatic shell conditional. -q suppresses output and exits early on the first match.

The four rules that would have caught all five

  1. Use [[ ]], not [ ], whenever you have bash. It removes the empty-variable and word-splitting failures by construction.
  2. Quote the left, think about the right. Quoting the right-hand side turns a pattern into a literal — sometimes what you want, often not.
  3. Numbers use (( )) or -gt, never > and < inside a test.
  4. Prefer testing a command over testing a string. if systemctl is-active --quiet nginx is more honest than parsing the output of systemctl status.

shellcheck catches every one of these five, plus several you have not thought of. It should be a required gate in your pipeline — a linter that knows the language better than you do is the cheapest engineer you will ever hire.

Part B · regex

Regular expressions — and the three dialects

The building blocks

.        any single character
^  $     start / end of line
[abc]    one of a b c
[^abc]   NOT one of them
[0-9]    a digit
\w \d \s word, digit, space (PCRE)
*        0 or more
+        1 or more     (ERE)
?        0 or 1        (ERE)
{2,5}    between 2 and 5
(ab|cd)  group + alternation (ERE)
\1       backreference
\b       word boundary

Anchor everything. [0-9]+ matches the 7 inside abc7def. If you mean "is entirely digits", write ^[0-9]+$. Unanchored validation patterns are a standard security bug.

Three dialects, one lecture of pain

FlavourToolsNote
BRE basicgrep, sed+ ? { } ( ) | must be backslashed to be special
ERE extendedgrep -E, sed -E, awk, [[ =~ ]]Those characters are special as written. Prefer this.
PCREgrep -P, perl, pythonAdds \d \w \s, lazy *?, lookarounds

This table explains the classic frustration: a pattern that works in Python fails in grep because \d is PCRE-only, and one that works in grep -E fails in plain grep because + is literal in BRE. Use -E everywhere and be consistent.

In practice

# bash native — captures in BASH_REMATCH
if [[ "$line" =~ ^([0-9.]+)\ .*\ ([0-9]{3})\ ]]; then
    ip="${BASH_REMATCH[1]}"
    status="${BASH_REMATCH[2]}"
fi
# NOTE: the pattern must be UNQUOTED to be a regex.
# Store complex patterns in a variable instead:
re='^[0-9]+$';  [[ "$n" =~ $re ]]

# grep / sed / awk
grep -E '^(WARN|ERROR)' app.log
grep -oE '[0-9]{1,3}(\.[0-9]{1,3}){3}' app.log
sed -E 's/([0-9]{4})-([0-9]{2})/\2\/\1/' f
awk '$9 ~ /^5/ {print $7}' access.log

When not to use a regex. Structured formats are not text — parse them with a parser. jq for JSON, yq for YAML, xmllint/an XML library for XML. A regex over HTML or JSON works on your five test cases and fails on the sixth in a way you cannot predict. Also beware catastrophic backtracking: nested quantifiers like (a+)+$ can take exponential time on a crafted input, which is a genuine denial-of-service vector (ReDoS). If a pattern is longer than a line, that is a message: use a real parser, or write it in Python.

Part C · scheduling

The whole course, in one job

#!/usr/bin/env bash
# rotate-and-report.sh — archive yesterday's logs, purge old
# archives, mail a summary.  Usage: rotate-and-report.sh [--dry-run]
# Exit: 0 ok · 2 usage · 3 preflight · 4 archive · 5 report
set -euo pipefail
shopt -s nullglob
umask 077

readonly LOG_DIR=/var/log/nginx  ARCHIVE_DIR=/var/archive/nginx
readonly RETENTION_DAYS=30  STAMP=$(date -d yesterday +%F)
readonly HEARTBEAT=/var/lib/rotate/last-success
dry_run=0

case "${1:-}" in --dry-run) dry_run=1 ;; "") ;; *) usage ;; esac

log() { printf '%s [%s] %s\n' "$(date -Is)" "$1" "${*:2}"; }
run() { (( dry_run )) && { log DRY "$*"; return 0; }; "$@"; }

# --- preflight: fail fast, with a distinct code -----------------
exec 9>/var/lock/rotate.lock; flock -n 9 || { log WARN "running"; exit 0; }
mountpoint -q /var/archive || { log ERROR "archive not mounted"; exit 3; }
command -v gzip >/dev/null || { log ERROR "gzip missing"; exit 3; }

# --- archive ---------------------------------------------------
logs=( "$LOG_DIR"/*.log )
(( ${#logs[@]} )) || { log INFO "nothing to rotate"; exit 0; }
for f in "${logs[@]}"; do
    run mv -- "$f" "$ARCHIVE_DIR/${f##*/}-$STAMP"
done
run nginx -s reopen
run gzip -9 "$ARCHIVE_DIR"/*-"$STAMP"
(( dry_run )) || gzip -t "$ARCHIVE_DIR"/*-"$STAMP".gz || { log ERROR "bad archive"; exit 4; }

# --- retention (destructive: narrow, named, logged) -------------
run find "${ARCHIVE_DIR:?}" -maxdepth 1 -type f -name '*.gz' \
         -mtime +"$RETENTION_DAYS" -print -delete

# --- report + heartbeat ----------------------------------------
run summarise "$ARCHIVE_DIR" | run mail -s "[$(hostname -s)] $STAMP" ops@example.com
(( dry_run )) || date -Is > "$HEARTBEAT"
log INFO "done: ${#logs[@]} logs"

And the schedule

# /etc/cron.d/rotate-and-report  (0644 root:root)
SHELL=/bin/bash
PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
MAILTO=ops@example.com

17 2 * * * logsvc /usr/local/bin/rotate-and-report \
    >> /var/log/rotate/rotate.log 2>&1

# independent dead-man's switch — the job that
# watches the job
0 9 * * * ops /usr/local/bin/check-heartbeat \
    /var/lib/rotate/last-success 26h

Every unit is present

  • U1 — it is a repeatable, versioned, reviewable process.
  • U2 — rotation, retention, reporting; verify before deleting; alert on absence.
  • U3 — cron.d, explicit SHELL and PATH, both streams redirected, locked, off the hour.
  • U4 — a service account, FHS paths, the mount check, umask 077.
  • U5 — shebang, strict mode, readonly, case, ${:?}, ${f##*/}, arrays, dry-run, exit codes.

Note the run wrapper: one three-word function gives the entire script a dry-run mode. That is the cheapest safety feature in shell scripting.

Part D · best practice

Best practices for scripting — the review checklist

Correctness

  • Shebang; set -euo pipefail.
  • Every expansion quoted; shellcheck clean.
  • Arguments validated; ${x:?} before anything destructive.
  • Idempotent — safe to run twice.
  • Preflight assertions: commands present, paths mounted, space free, permissions right.
  • Verify results, do not assume: test the archive, check the health endpoint.
  • Meaningful, documented exit codes.

Operability

  • --dry-run, and make it the default for destructive tools.
  • Timestamped logs to stderr; logger for the journal.
  • flock against overlapping runs.
  • trap cleanup on EXIT, INT and TERM.
  • A heartbeat, and an independent watcher that alerts on its absence.
  • Configuration in a file or environment — never constants edited in place.
  • Rotate the log your own script writes.

Maintainability & security

  • Header block: purpose, usage, assumptions, exit codes, owner.
  • Functions with local; main "$@" at the bottom.
  • Comment the why, never the what.
  • In version control, code-reviewed like any other code.
  • Tested — bats, or at minimum a documented manual test including the failure paths.
  • Runs as a dedicated service account with least privilege.
  • No secrets in the script, in Git, on a command line, or in the environment.
  • Know when to stop. Past roughly 300 lines, or when you need data structures, arithmetic on floats or real error handling, rewrite it in Python. Shell is a magnificent glue language and a poor programming language.

DevOps Automation, in one slide

Unit 1

A pipeline moves change from commit to user through gates ordered by cost. Automating it buys repeatability first, speed second.

Unit 2

Fourteen real scenarios, six ideas: verify, be idempotent, validate at the boundary, stay reversible, alert on absence, protect secrets.

Unit 3

cron runs it without you — with an empty environment, no retries and no memory. Everything must be declared, redirected, locked and watched.

Unit 4

A file is an inode, a path is not a disk, and every job runs as somebody — choose that identity deliberately and give it the least it needs.

Unit 5

The first fifteen lines decide everything. Quote every expansion, comment the why, and know when to stop writing shell.

Automation does not remove human error. It moves it to a place where it can be reviewed, tested and fixed before it costs anything.
