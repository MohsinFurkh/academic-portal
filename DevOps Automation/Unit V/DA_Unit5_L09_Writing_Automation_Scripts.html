Part A · the skeleton

Always begin with a shebang

The first two bytes #! tell the kernel which interpreter to run the file with. Without it, what happens depends on who invokes you — a hidden dependency on the caller's shell.

FormMeaningUse when
#!/bin/shPOSIX shell — dash on Debian/UbuntuStrict portability; no bash features at all
#!/bin/bashbash at a fixed pathLinux system scripts; bash is always at /bin/bash
#!/usr/bin/env bashThe first bash on PATHPortable across macOS/BSD, where bash may be elsewhere — the usual default
#!/usr/bin/env python3Same idea for any interpreterRespects virtualenvs

The trade-off: env finds whichever bash is first on PATH — good for portability, but it means a user's modified PATH chooses your interpreter. For a root-owned system script, the fixed /bin/bash is the safer choice.

The production skeleton — memorise this

#!/usr/bin/env bash
#
# archive-reports.sh — archive PDFs and purge the source
#
# Usage:   archive-reports.sh [--dry-run] <dir> <days>
# Author:  ops@example.com    Repo: git@…/ops-scripts
# Exit:    0 ok · 2 usage · 3 preflight failed · 4 archive failed

set -euo pipefail
IFS=$'\n\t'

readonly SCRIPT_NAME=${0##*/}
readonly LOCK_FILE="/var/lock/${SCRIPT_NAME}.lock"

usage() { sed -n '3,8p' "$0" >&2; exit 2; }
log()   { printf '%s [%s] %s\n' "$(date -Is)" "$1" "${*:2}" >&2; }
die()   { log ERROR "$*"; exit "${EXIT_CODE:-1}"; }

WORK=$(mktemp -d)
trap 'rc=$?; rm -rf -- "$WORK"; exit $rc' EXIT
trap 'die "interrupted"' INT TERM
Part B · built-in options

Make use of the shell's built-in options

set — the strict-mode trio

OptionEffect
set -eExit immediately if any command fails. Without it, a failed cd is followed cheerfully by rm -rf * in the wrong directory.
set -uTreat an unset variable as an error. Catches typos and missing arguments before they expand to nothing.
set -o pipefailA pipeline fails if any stage fails. By default only the last command's status counts, so false | wc -l "succeeds".
set -xPrint each command after expansion. The debugging tool. Pair with PS4='+${BASH_SOURCE}:${LINENO}: '.
set -nParse without executing — a free syntax check for CI.

IFS=$'\n\t' removes the space from the word-splitting set, so unquoted expansions no longer split on spaces. It is a safety net, not a substitute for quoting.

set -e is not magic — know its holes

  • It does not trigger for a command in a condition: if cmd; then, while cmd, cmd && other, ! cmd. That is deliberate and usually what you want.
  • The trap that catches everyone: count=$(grep -c x f) under set -e exits when grep finds nothing (status 1). Write count=$(grep -c x f || true).
  • A function called in a condition loses -e inside it too.
  • Test both paths — -e gives a false sense of safety if you have never watched your script fail.

shopt — the ones worth setting

shopt -s nullglob   # *.log with no matches → nothing,
                    # not the literal string "*.log"
shopt -s failglob   # or: make it an error
shopt -s globstar   # ** matches across directories
shopt -s inherit_errexit  # -e inside $( )

nullglob fixes a real bug: without it, for f in *.log in an empty directory loops once with f set to the literal *.log.

Builtins over external commands. [[ ]], printf, ${var##*/} and $(( )) run inside the shell; [, echo(sometimes), expr, basename and seq fork a process each call. In a 100,000-iteration loop that is the difference between one second and several minutes. Use type -a name to see which you are getting.

Part C · naming & annotation

Naming conventions

Variables

# Environment / exported: UPPER_SNAKE
export DATABASE_URL

# Script constants: UPPER, readonly
readonly MAX_RETRIES=5
readonly ARCHIVE_DIR=/var/archive

# Local / internal: lower_snake
local retry_count=0
target_file="$1"

# ALWAYS declare function locals
process() { local f="$1" n=0; …; }

Why the case split matters: shell variables share one global namespace with the environment. A variable named PATH or IFS or HOME in your script overwrites something the system depends on. Lower case for your own values keeps you out of that space.

Functions and files

# verb_noun, lower_snake, no `function` keyword
archive_reports() { …; }
validate_input()  { …; }
require_command() { …; }

# Prefix internal helpers
_cleanup_temp() { …; }

Files: backup-database.sh — lower case, hyphens, a verb, .sh for shell. Name it after what it does, not what it operates on: rotate-nginx-logs.sh, not nginx.sh. Once installed in /usr/local/bin, drop the extension — users type rotate-nginx-logs, and the extension is an implementation detail that will be wrong if you rewrite it in Python.

Rules that prevent real bugs

  • Never name a variable after a command you also call — test, date, time.
  • Do not shadow the specials: PATH, IFS, HOME, PWD, UID, RANDOM, SECONDS.
  • Say what the unit is: timeout_seconds, size_mb, retention_days. Half of all off-by-1000 bugs are unit confusion.
  • Name booleans as a question: is_dry_run, has_lock.
  • readonly your constants. The shell will then stop you reassigning them 300 lines later.
Part C · naming & annotation

Annotations that make the logic clean

Comments that earn nothing

# set i to 0
i=0

# loop through the files
for f in *.log; do

# remove the file
rm -f "$f"

# increment counter
((i++))

These restate the code, so they add reading time and nothing else — and worse, they rot. When the code changes and the comment does not, the comment becomes a confident lie, and the next reader believes it over the code.

Comments that carry information the code cannot

# The vendor's SFTP drops connections above 4 parallel
# streams and returns a misleading 550. Ticket VEN-4412.
readonly MAX_PARALLEL=4

# mysqldump exits 0 on a partial dump if the connection
# drops mid-table, so we assert the trailer explicitly.
zcat "$OUT" | tail -1 | grep -q 'Dump completed'

# NOTE: the reopen signal MUST follow the rename, or nginx
# keeps writing to the moved inode. See lecture 3.
nginx -s reopen

# TODO(mohsin, 2026-10): replace with systemd timer once
#   the fleet is on Ubuntu 24.04.

The rule: comment the why, never the what. The code already states what it does. Reserve comments for the reason, the constraint, the ticket, the surprising behaviour of an external tool, and the thing you tried that did not work.

The header block is the most valuable annotation

Name, one-line purpose, usage synopsis, what it assumes about the environment, the exit codes it returns, and who to contact. It costs six lines and answers every question the person woken at 3 a.m. will have. Make usage() print it, so the documentation cannot drift from the script — it is the script.

Structure is an annotation too

Named functions beat comments. A block commented # validate the inputs should be a function called validate_inputs — now the label is checked by the machine, is reusable, and cannot drift. Keep main "$@" at the bottom so the top-level flow reads as a summary of the script in six lines.

Part D · substitution

Variable substitution

Defaults and assertions

${var}            # braces: always safe
${var:-def}       # use def if unset/empty
${var-def}        # use def only if UNSET
${var:=def}       # ...and assign it
${var:?msg}       # ABORT with msg if unset
${var:+alt}       # alt only if var IS set

# The one that prevents disasters:
DIR="${1:?usage: script <dir>}"
rm -rf -- "${DIR:?refusing empty}"/*

${DIR:?} makes an empty or unset path a hard stop rather than a catastrophe. Put it on every destructive line.

Trimming and replacing

f=/var/log/app/access.log.gz
${f##*/}    → access.log.gz   # basename
${f%/*}     → /var/log/app    # dirname
${f%.gz}    → …/access.log    # drop suffix
${f%%.*}    → /var/log/app/access
${f/log/LOG}  # replace first
${f//log/LOG} # replace all
${#f}       → 26              # length
${f^^}  ${f,,}  # upper / lower
${f:5:3}    → r/l             # substring

Mnemonic: # is left of $ on the keyboard so it trims from the left; % is right of it so it trims from the right. Doubling the character makes the match greedy. These are builtins — far faster than basename/dirname, which fork.

Quoting — the rule

f="my report.pdf"
rm $f       # TWO files: "my", "report.pdf"
rm "$f"     # correct

# Arrays: "${a[@]}" is the ONLY correct form
files=("a b.txt" "c.txt")
for f in "${files[@]}"; do …   # 2 items ✓
for f in ${files[@]};  do …   # 3 items ✗
"${files[*]}"   # ONE string, joined by $IFS

"$@"   # each argument preserved ✓
"$*"   # all arguments as one string

Quote every expansion. The exceptions are so rare that "always quote" is the correct rule to memorise. Word splitting and globbing happen after substitution — quoting is what stops them.

Part D · substitution

Command substitution

now=$(date +%F)          #  ✓ modern form
now=`date +%F`            #  ✗ backticks: legacy

# $( ) nests cleanly; backticks need escaping:
$(dirname "$(readlink -f "$0")")     # ✓
`dirname \`readlink -f $0\``           # ✗

# Arithmetic — its own construct, no $ inside
total=$(( count * size ))
(( retries > MAX )) && die "too many"

# Process substitution: a command that looks like a file
diff <(sort a.txt) <(sort b.txt)
while read -r line; do …; done < <(find . -name '*.log')

Why the last form matters: find … | while read runs the loop in a subshell, so any variable it sets is lost when the pipeline ends. Feeding it with < <(…) keeps the loop in the current shell. This is the cause of "my counter is always 0 after the loop".

Four traps

  • Trailing newlines are stripped — usually helpful, occasionally not. To keep them: out=$(cmd; printf x); out=${out%x}.
  • Unquoted output is split and globbed. files=$(ls) then rm $files breaks on every name containing a space. Never parse ls; use a glob or find -print0 with read -d ''.
  • The exit status is the inner command's, and it is easy to discard: out=$(cmd) propagates it, but local out=$(cmd) does not — local succeeds, masking the failure. Declare first, assign second.
  • Every $( ) forks a subshell. Inside a large loop this dominates runtime. Prefer parameter expansion where it will do.

And never build a command as a string and eval it — that is Lecture 4's injection, reintroduced. Use an array: cmd=(rsync -a "$src" "$dst"); "${cmd[@]}".

Reveal · the nine defects

Slide 2, repaired

#!/usr/bin/env bash
# archive-reports.sh — archive PDFs, then purge the source.
# Usage: archive-reports.sh <dir> <days>   Exit: 0 ok · 2 usage · 3 preflight
set -euo pipefail
shopt -s nullglob
umask 077

readonly DIR="${1:?usage: archive-reports.sh <dir> <days>}"
readonly DAYS="${2:?usage: archive-reports.sh <dir> <days>}"
readonly DEST=/backup
[[ "$DAYS" =~ ^[0-9]+$ ]] || { echo "days must be numeric" >&2; exit 2; }
[[ -d "$DIR" ]]              || { echo "no such dir: $DIR" >&2; exit 3; }
mountpoint -q "$DEST"       || { echo "$DEST not mounted" >&2; exit 3; }

# Only one run at a time; a slow run must not overlap the next.
exec 9>/var/lock/archive-reports.lock
flock -n 9 || { echo "already running" >&2; exit 0; }

WORK=$(mktemp -d)
trap 'rc=$?; rm -rf -- "$WORK"; exit $rc' EXIT

pdfs=( "$DIR"/*.pdf )
(( ${#pdfs[@]} )) || { echo "nothing to archive"; exit 0; }

archive="$WORK/reports-$(date +%F).tar.gz"
tar czf "$archive" -C "$DIR" -- "${pdfs[@]##*/}"
tar tzf "$archive" >/dev/null          # VERIFY before deleting anything

mv -n -- "$archive" "$DEST/"           # -n: never clobber a previous archive
find "$DIR" -maxdepth 1 -type f -name '*.pdf' -mtime +"$DAYS" -print -delete
logger -t archive-reports "archived ${#pdfs[@]} files from $DIR"

The nine

  1. #!/bin/sh with bash intentions → correct shebang.
  2. No error handling — every failure was ignored → set -euo pipefail.
  3. cd $DIR unquoted and unchecked; if it fails the script carries on and deletes in the current directory → validate, and never cd at all.
  4. No argument validation — missing arguments expanded to nothing → ${1:?} plus a numeric check.
  5. *.pdf with no matches passed the literal string to tar → nullglob and an explicit count check.
  6. Predictable temp file in /tmp — a symlink attack, and a collision between two runs → mktemp -d with a cleanup trap.
  7. Deleted the source without verifying the archive → tar tzf first. The defect that lost the data.
  8. rm -rf $DIR/* deleted everything, not just archived PDFs older than $DAYS — and would have deleted /* had $DIR been empty → a narrow, name-filtered, age-filtered find.
  9. No locking and no logging → flock and logger.

Bonus: backticks, and mv without -n silently overwriting yesterday's archive.
