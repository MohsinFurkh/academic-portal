Decision Trees, Random Forests, and Gradient Boosting

Leave the hyperplane behind. A tree carves the input space into boxes; a forest averages many de-correlated trees; boosting fits each new tree to what the ensemble still gets wrong. Two of these are still the best thing to run on tabular data.

By the end you can

  • Derive the optimal leaf value for a fixed partition, and see why finding the best tree is intractable
  • Derive why misclassification error fails as a splitting criterion and Gini and entropy do not
  • Derive \(\Var\!\left(\bar f\right)=\rho\sigma^2+\frac{1-\rho}{B}\sigma^2\) and read random forests off it
  • Derive gradient boosting as gradient descent in function space
  • Derive the second-order leaf value \(w^\star=-G/(H+\lambda)\) and the split-gain formula behind XGBoost
  • Say precisely which of bias and variance each ensemble method attacks

1A completely different way to be nonlinear

Everything in Part II fitted a function of the form \(f(\vx)=\vw^\top\phi(\vx)\): you choose the basis \(\phi\) up front and the model chooses the weights. Trees abandon that entirely. A tree makes no smoothness assumption, has no coefficients, and is invariant to any monotone transformation of any individual feature — take logs of half your columns and the tree is unchanged.

Intuition

A tree is a game of twenty questions. Each internal node asks one question of the form "is \(x_j \le t\)?", and after a few questions you land in a leaf and answer with whatever the training points in that leaf averaged to.

Geometrically: each question is an axis-aligned cut, and the questions together carve \(\RR^d\) into rectangular boxes. The fitted function is constant on each box. That is the entire model class — piecewise constant on axis-aligned boxes.

Regression tree

A partition of the input space into \(M\) disjoint regions \(R_1,\dots,R_M\) formed by axis-aligned splits, together with a value per region:

\[ f(\vx) \;=\; \sum_{m=1}^{M} c_m \,\mathbb{1}[\vx \in R_m]. \]

For classification the leaf holds a class distribution \(\hat p_{mk}\) instead of a single number, and predicts \(\argmax_k \hat p_{mk}\).

Given the boxes, the leaf values are immediate0 / 4
\[\hat R(f)=\sum_{i=1}^{n}\big(y_i-f(\vx_i)\big)^2 = \sum_{m=1}^{M}\ \sum_{i:\,\vx_i\in R_m}\big(y_i-c_m\big)^2\]
The objective splits over regions. Because the regions are disjoint and cover everything, each training point contributes to exactly one inner sum. So the \(M\) leaf values are \(M\) completely independent one-parameter problems — no coupling at all, unlike the normal equations where every coefficient depends on every other.
\[\frac{\partial}{\partial c_m}\sum_{i\in R_m}(y_i-c_m)^2 = -2\sum_{i\in R_m}(y_i-c_m)=0 \;\Longrightarrow\; \hat c_m = \frac{1}{|R_m|}\sum_{i\in R_m} y_i\]
Each leaf is the mean. Phase A Lecture 13's result again: the constant minimising squared deviation is the mean. The second derivative is \(2|R_m|>0\), so it is a minimum.
\[\text{0–1 loss} \Rightarrow \hat c_m = \text{majority class}, \qquad \text{absolute loss} \Rightarrow \hat c_m = \text{median}\]
The leaf value is decided by the loss, not by the tree. Exactly the correspondence from Lecture 4: squared loss → mean, absolute loss → median, 0–1 loss → mode. Change the loss and only this step changes; the partition machinery is untouched.
\[\text{but choosing } \{R_m\} \text{ optimally is NP-hard}\]
The hard half. The number of distinct binary trees over \(n\) points with \(d\) features is astronomically large, and finding the partition that minimises \(\hat R\) is NP-hard (Hyafil & Rivest, 1976). So every tree algorithm in existence is greedy: choose the single best split now, recurse, never reconsider. Nothing guarantees the result is close to optimal — it is a heuristic, and calling it one is more honest than most textbooks are.

2Choosing a split: impurity, and a criterion that quietly fails

For regression, "best split" means the one that most reduces the sum of squared errors, and the code below shows the \(O(n\log n)\) prefix-sum trick that makes it fast. For classification we need a measure of how mixed a node is. Three candidates, all functions of the class proportions \(p_k\) in a node:

Impurity measures

\[ \text{misclassification: } \ I_{\text{err}} = 1-\max_k p_k, \qquad \text{Gini: } \ I_G = \sum_k p_k(1-p_k), \qquad \text{entropy: } \ I_H = -\sum_k p_k\log_2 p_k. \]

All three are zero for a pure node and maximal at the uniform distribution. The gain of a split is the parent impurity minus the size-weighted average of the children's:

\[ \Delta = I(\text{parent}) - \frac{n_L}{n}I(\text{left}) - \frac{n_R}{n}I(\text{right}). \]

Why misclassification error is the wrong criterion0 / 5
\[\Delta \;=\; I(\bar p) - \Big[\tfrac{n_L}{n}I(p_L)+\tfrac{n_R}{n}I(p_R)\Big], \qquad \bar p=\tfrac{n_L}{n}p_L+\tfrac{n_R}{n}p_R\]
Set up the geometry. First check the identity \(\bar p = \frac{n_L}{n}p_L+\frac{n_R}{n}p_R\): the parent's class-1 proportion is the size-weighted average of the children's, because the counts simply add. So the gain compares the height of \(I\) at a weighted average against the weighted average of the heights.
\[\Delta \ge 0 \ \text{ for all splits} \iff I \text{ is concave}\]
That is exactly Jensen's inequality. \(I(\text{weighted average}) \ge \text{weighted average of } I\) is the definition of concavity. So any concave impurity gives non-negative gain, and the gain is the vertical gap between the curve and the chord joining \((p_L,I(p_L))\) to \((p_R,I(p_R))\). Draw that chord in the figure below — it is the whole story in one picture.
\[I_{\text{err}}(p)=\min(p,1-p) \ \text{ is concave but } \textbf{piecewise linear}\]
Here is the defect. Concave, so the gain is never negative — but only weakly concave. On either side of \(p=\tfrac12\) it is a straight line, and a chord between two points on a straight line lies exactly on it. Gain zero.
\[p_L,p_R \ \text{ on the same side of } \tfrac12 \ \Longrightarrow\ \Delta_{\text{err}}=0\]
The consequence. Any split whose two children still have the same majority class scores exactly zero under misclassification error, no matter how much it purifies them. The greedy search sees a flat landscape and stops. Concretely: a parent with 400/400 split into (300,100) and (100,300) and split into (200,0) and (200,400) both score \(\Delta_{\text{err}}=0.25\) — indistinguishable, although the second produces a perfectly pure leaf.
\[I_G(p)=2p(1-p) \ \text{ and } \ I_H(p) \ \text{ are } \textbf{strictly} \text{ concave}\]
The fix. \(I_G''(p)=-4<0\) everywhere and \(I_H''(p)=-\frac{1}{\ln 2}\big(\frac1p+\frac1{1-p}\big)<0\) everywhere. Strict concavity means the chord is strictly below the curve whenever \(p_L\neq p_R\), so every non-trivial split gets strictly positive credit and the greedy search always has a gradient to follow. This is why sklearn offers gini and entropy and not error — and why you still use misclassification error for pruning, where you are comparing whole trees rather than searching for a split.

3Growing, and then not growing too far

The recursion is: find the best split by scanning every feature and every candidate threshold, apply it, recurse on both children, stop at a depth limit or a minimum leaf size. A fully grown tree with \(n\) distinct points has \(n\) leaves and interpolates the training data exactly — training error zero, test error terrible. Depth is the capacity knob, and Lecture 7's U-shaped test curve appears in its cleanest form.

Practical engineering note

Pre-pruning vs post-pruning. Stopping early on a depth or minimum-leaf-size rule (pre-pruning) is fast but short-sighted: a split that looks useless can enable an excellent split beneath it — the XOR pattern is the standard example, where neither first split reduces impurity at all. Cost-complexity pruning (post-pruning) grows the tree fully and then prunes back to minimise \(\hat R(T)+\alpha|T|\) over subtrees, choosing \(\alpha\) by cross-validation. The penalty \(\alpha|T|\) is the same regularisation idea as Lecture 6, with the number of leaves playing the role of the norm.

In practice, when a tree is going into an ensemble, people mostly skip pruning: the ensemble handles the variance. Pruning matters when you are shipping the single tree because someone wants to read it.

Common trap

Trees are unstable, and this is their defining flaw. Change one training point and the top split can change; if it does, the entire tree below it is rebuilt and the fitted function can be unrecognisable. In Lecture 7's terms: very low bias (a deep tree can fit anything), very high variance.

Everything in the rest of this lecture is a response to that one sentence. Bagging averages the variance away. Boosting takes the opposite route — deliberately use high-bias, low-variance stumps and remove the bias by addition. Two opposite fixes for two opposite starting points, which is why you must know which problem you have before choosing.

4Bagging: averaging away the variance

If \(B\) independent estimators each have variance \(\sigma^2\), their average has variance \(\sigma^2/B\). We do not have \(B\) independent training sets, so we fake them: draw \(B\) bootstrap resamples of the training data (sample \(n\) rows with replacement), fit a tree to each, average the predictions. That is bagging — bootstrap aggregating.

But the trees are not independent — they see overlapping data. The next derivation is the single most important formula in ensemble learning, because it tells you exactly what that dependence costs.

The variance of an average of correlated estimators0 / 6
\[\Var\Big(\frac1B\sum_{b=1}^{B} f_b\Big) = \frac{1}{B^2}\Big[\sum_{b}\Var(f_b) + \sum_{b\ne b'}\Cov(f_b,f_{b'})\Big]\]
Expand the variance of a sum. Phase A Lecture 13: \(\Var(\sum_b f_b)=\sum_b\Var(f_b)+\sum_{b\ne b'}\Cov(f_b,f_{b'})\), and the \(1/B\) outside squares to \(1/B^2\). The cross terms are the whole point — dropping them is the mistake that makes people expect \(\sigma^2/B\).
\[\Var(f_b)=\sigma^2 \ \ \forall b, \qquad \Cov(f_b,f_{b'})=\rho\sigma^2 \ \ \forall b\ne b'\]
The exchangeability assumption. The trees are built by an identical random procedure on the same training set, so they are exchangeable: same marginal variance \(\sigma^2\), same pairwise correlation \(\rho\). Reasonable, and the code below checks it holds well enough to predict the answer to a few percent.
\[= \frac{1}{B^2}\Big[B\sigma^2 + B(B-1)\rho\sigma^2\Big]\]
Count the terms. There are \(B\) diagonal terms and \(B(B-1)\) off-diagonal ordered pairs. The cross terms outnumber the diagonal ones by a factor of \(B-1\) — which is why they dominate for large \(B\).
\[\boxed{\ \Var\Big(\frac1B\sum_b f_b\Big) \;=\; \rho\sigma^2 \;+\; \frac{1-\rho}{B}\,\sigma^2\ }\]
Simplify. \(\frac{1}{B}\sigma^2+\frac{B-1}{B}\rho\sigma^2 = \rho\sigma^2+\frac{1-\rho}{B}\sigma^2\). Read the two terms: the second vanishes as \(B\to\infty\), the first does not.
\[\lim_{B\to\infty}\Var = \rho\sigma^2 \;>\;0 \quad\text{whenever } \rho>0\]
The floor. No number of trees ever gets you below \(\rho\sigma^2\). Adding trees past the point where \(\frac{1-\rho}{B}\sigma^2 \ll \rho\sigma^2\) — that is, past \(B\approx\frac{1-\rho}{\rho}\) — is wasted computation. This is why \"just use more trees\" stops helping, and it also tells you the only two ways forward: lower \(\rho\), or lower \(\sigma^2\).
\[\text{random forest: lower } \rho \text{ by choosing splits from a random subset of } m<d \text{ features}\]
And that is a random forest. Bagging alone leaves \(\rho\) high because every tree finds the same dominant feature and splits on it first. Restricting each node to a random subset of \(m\) features forces different trees down different paths, cutting \(\rho\). But it also makes each individual tree worse, raising \(\sigma^2\) — so \(m\) is a hyperparameter with an interior optimum, and the code below measures both effects separately instead of taking the usual \(m=\sqrt d\) on faith.

Where this shows up in ML

Out-of-bag error, free of charge. A bootstrap sample of size \(n\) omits each particular row with probability \((1-1/n)^n \to e^{-1}\approx 0.368\). So every training row is out-of-bag for about 37% of the trees, and you can predict it using exactly those trees. Averaging the error over all rows gives an almost-unbiased estimate of test error with no held-out set and no cross-validation refits. Lecture 7 spent a whole section on how to buy an honest error estimate; the bootstrap hands one over as a by-product.

The caveat: OOB uses an ensemble of about \(0.37B\) trees rather than \(B\), so it is very slightly pessimistic. With \(B\) in the hundreds the difference is negligible.

5Boosting: fitting what the ensemble still gets wrong

Bagging builds its trees in parallel and independently. Boosting builds them sequentially, each one trained on the mistakes of everything built so far. The models are deliberately weak — depth-1 or depth-3 stumps with enormous bias — and the ensemble removes that bias by accumulation. Same ingredient, opposite recipe, opposite failure mode.

Gradient boosting is gradient descent in function space0 / 6
\[\min_{F}\ \hat R(F) = \sum_{i=1}^{n} L\big(y_i, F(\vx_i)\big)\]
Change the variable we optimise over. Until now we minimised over a parameter vector \(\vw\). Here the variable is the function \(F\). But \(\hat R\) only ever touches \(F\) through the \(n\) numbers \(F(\vx_1),\dots,F(\vx_n)\), so for the purpose of differentiating we can treat \(\vF=(F(\vx_1),\dots,F(\vx_n))\in\RR^n\) as an ordinary vector. That reduction is what makes the whole idea work.
\[g_i \;=\; \frac{\partial L(y_i,F(\vx_i))}{\partial F(\vx_i)}, \qquad \vF \leftarrow \vF - \nu\,\vg\]
Take one gradient-descent step in \(\RR^n\), with step size \(\nu\). Exactly Lecture 3, with the \(n\) function values as the parameters. For squared loss \(L=\tfrac12(y-F)^2\) we get \(g_i=F(\vx_i)-y_i\), so \(-g_i=y_i-F(\vx_i)\) is the residual. The famous \"fit the residual\" rule is not a heuristic — it is the negative gradient of squared loss, and nothing more.
\[\text{problem: } -\vg \ \text{is defined only at the } n \text{ training points}\]
The obstacle. A step in \(\RR^n\) tells us how to change \(F\) at the training inputs and says nothing about anywhere else. But we need a function we can evaluate on new data. Descent in \(\RR^n\) alone would just memorise the training set.
\[h_m \;=\; \argmin_{h\in\mathcal{H}} \sum_{i=1}^{n}\big(-g_i - h(\vx_i)\big)^2\]
Project the gradient onto the model class. Fit a small tree to the negative gradients by least squares — find the member of \(\mathcal H\) that best approximates the step we wanted to take. The tree generalises the direction to the whole input space. Note this is a least-squares fit regardless of what \(L\) is: the loss enters only through the targets \(-g_i\), which is exactly why one implementation handles every differentiable loss.
\[F_m(\vx) \;=\; F_{m-1}(\vx) \;+\; \nu\, h_m(\vx), \qquad F_0 = \argmin_c \textstyle\sum_i L(y_i,c)\]
Take the step. \(\nu\in(0,1]\) is the learning rate, called shrinkage here. It is Lecture 3's step size, and it plays the same role: small steps in a direction that is only approximately right end up ahead of large ones. Empirically \(\nu\approx0.1\) with many rounds beats \(\nu=1\) with few, and the code block measures the gap.
\[F_M = F_0 + \nu\sum_{m=1}^{M} h_m \quad\text{— an additive model, fitted greedily, stage by stage}\]
What we have built. \(M\) and \(\nu\) trade off against each other (roughly \(\nu M \approx\) constant), so tune one and fix the other. Unlike bagging, more rounds eventually overfit: the ensemble keeps chasing residuals that are pure noise, so \(M\) must be chosen by a validation set — early stopping is not optional here, it is the main regulariser.

6The second-order version: where XGBoost comes from

Gradient boosting takes a first-order step. If we keep the second-order term as well, we get a Newton step in function space — and out of that falls a closed form for the leaf values and a principled split criterion. This derivation is the core of XGBoost, LightGBM and CatBoost, and it is short.

Newton boosting: the leaf value and the gain formula0 / 6
\[\hat R(F_{m-1}+h) \approx \sum_{i=1}^{n}\Big[L(y_i,F_{m-1}(\vx_i)) + g_i h(\vx_i) + \tfrac12 h_i\, h(\vx_i)^2\Big] + \Omega(h)\]
Second-order Taylor expansion in the function value, Phase A Lecture 6 applied per point, with \(g_i=\partial_F L\) and \(h_i=\partial^2_F L\) evaluated at the current \(F_{m-1}(\vx_i)\). \(\Omega\) is a regulariser on the new tree. The constant first term does not involve \(h\), so drop it.
\[\Omega(h)=\gamma T + \tfrac{\lambda}{2}\sum_{j=1}^{T} w_j^2, \qquad h(\vx)=\sum_{j=1}^{T} w_j\,\mathbb{1}[\vx\in R_j]\]
Say what the tree is and how we penalise it. \(T\) leaves, value \(w_j\) in leaf \(j\); \(\gamma\) charges per leaf (complexity control, as in cost-complexity pruning) and \(\lambda\) is a ridge penalty on the leaf values (Lecture 6, now applied to leaves instead of coefficients).
\[\text{obj} = \sum_{j=1}^{T}\Big[G_j w_j + \tfrac12 (H_j+\lambda) w_j^2\Big] + \gamma T, \qquad G_j=\!\!\sum_{i\in R_j}\!g_i,\ \ H_j=\!\!\sum_{i\in R_j}\!h_i\]
Regroup by leaf. Every training point lies in exactly one leaf, so \(\sum_i\) becomes \(\sum_j\sum_{i\in R_j}\), and inside a leaf \(h(\vx_i)=w_j\) is constant and comes out of the sum. The \(T\) leaves are now decoupled — the same decoupling as in the very first derivation of this lecture, and the reason everything closes in one line.
\[\frac{\partial}{\partial w_j}\Big[G_j w_j+\tfrac12(H_j+\lambda)w_j^2\Big]=G_j+(H_j+\lambda)w_j=0 \;\Longrightarrow\; \boxed{\,w_j^\star=-\frac{G_j}{H_j+\lambda}\,}\]
One-dimensional quadratic, minimised exactly. Second derivative \(H_j+\lambda>0\) for a convex loss, so it is a minimum. Sanity-check with squared loss: \(g_i=F-y_i\), \(h_i=1\), so \(G_j=-\sum_{i\in R_j}(y_i-F_i)\) and \(H_j=|R_j|\), giving \(w_j^\star=\frac{\sum(y_i-F_i)}{|R_j|+\lambda}\) — the mean residual, shrunk. At \(\lambda=0\) it is exactly the mean residual, so this reduces to ordinary gradient boosting, as it must. The code block verifies this to machine precision.
\[\text{obj}^\star = -\frac12\sum_{j=1}^{T}\frac{G_j^2}{H_j+\lambda} + \gamma T\]
Substitute \(w^\star\) back. \(G w^\star+\tfrac12(H+\lambda)w^{\star2} = -\frac{G^2}{H+\lambda}+\frac12\frac{G^2}{H+\lambda} = -\frac12\frac{G^2}{H+\lambda}\). This is a score for a tree structure with the leaf values already optimised out — smaller is better.
\[\text{Gain} = \frac12\left[\frac{G_L^2}{H_L+\lambda}+\frac{G_R^2}{H_R+\lambda}-\frac{(G_L{+}G_R)^2}{H_L{+}H_R+\lambda}\right]-\gamma\]
The split criterion, derived rather than chosen. Difference of the structure scores before and after splitting one leaf. Two things to notice. First, \(-\gamma\): a split must improve the score by at least \(\gamma\) or it is rejected — pruning built into the search. Second, at \(\lambda=\gamma=0\) with squared loss this reduces to \(\frac{(\sum_L r)^2}{n_L}+\frac{(\sum_R r)^2}{n_R}-\frac{(\sum r)^2}{n}\), which is precisely the prefix-sum criterion coded in best_split below. Everything is consistent.
Practical engineering note

What to actually do on a tabular problem in 2026.

  • Start with gradient-boosted trees (XGBoost / LightGBM / CatBoost). On tabular data with mixed types and a few thousand to a few million rows, they still beat neural networks in most careful benchmarks. This is not nostalgia — it is the one large domain where deep learning did not take over.
  • Tune \(\nu\) and \(M\) together, with early stopping. Fix \(\nu=0.05\)–\(0.1\), set \(M\) large, and stop when validation error stops improving. Then tune depth (3–8), min_child_weight (that is \(H_j\), the leaf's total Hessian) and subsampling.
  • Random forests when you want robustness with no tuning. Defaults work, it is trivially parallel, and OOB gives a free error estimate. It will rarely be the best model and rarely be a bad one.
  • Distrust impurity-based feature importances. They are biased toward high-cardinality and continuous features, which get more candidate split points and so more chances to look good on noise. Use permutation importance on held-out data, or SHAP values, and remember both still describe the model, not the world.
  • Trees cannot extrapolate. Every prediction is an average of training labels, so a tree's output is bounded by \([\min y_i, \max y_i]\) forever. On a time series with a trend, a tree will predict a flat line beyond the training range. This is a hard structural limit, not a tuning problem.

  1. What fraction of the training set does one tree actually see, for large \(n\)?
  2. How many of \(B=500\) trees is a given row out-of-bag for, on average?
  3. Explain why OOB error is slightly pessimistic compared with the full forest's test error.
  4. At \(n=10\), how far is \((1-1/n)^n\) from the limit? Does OOB still work at small \(n\)?

Proof. Each of the \(n\) independent draws picks item \(i\) with probability \(1/n\), so misses it with probability \(1-1/n\). The draws are independent, so all \(n\) miss it with probability \((1-1/n)^n\). Taking logs: \(n\log(1-1/n) = n\big(-\tfrac1n-\tfrac{1}{2n^2}-O(n^{-3})\big) = -1-\tfrac{1}{2n}+O(n^{-2}) \to -1\), so the probability \(\to e^{-1}=0.3679\). ∎

1. About \(1-0.368=63.2\%\) of the rows appear at least once (some several times, since the sample still has \(n\) elements).

2. \(500\times0.368\approx 184\) trees. That is a substantial ensemble, which is why the OOB estimate is usable rather than merely suggestive.

3. Because the OOB prediction for a row averages only those ~184 trees, not all 500. By the variance formula, an ensemble of \(B'=184\) has variance \(\rho\sigma^2+\frac{1-\rho}{184}\sigma^2\) versus \(\rho\sigma^2+\frac{1-\rho}{500}\sigma^2\) — strictly larger, so slightly higher expected error. With \(\rho\) of order 0.1 and \(B\) in the hundreds both terms are dominated by \(\rho\sigma^2\) and the gap is negligible; at \(B=20\) it is not.

4. \((1-1/10)^{10}=0.9^{10}=0.3487\) versus \(0.3679\) — about 5% low, matching the \(-\frac{1}{2n}\) correction term. So each row is OOB for ~35% of the trees. The estimator still works; the real problem at small \(n\) is that averaging errors over few rows is noisy, which is a sample-size issue, not a bootstrap issue.

Suppose all \(B\) trees in a forest are identical (\(\rho=1\)).

  1. What does the variance formula give? Verify it directly without the formula.
  2. Now suppose \(\rho<0\) is somehow achievable. What is the smallest possible variance, and what constraint on \(\rho\) makes the formula sensible?
  3. A colleague proposes de-correlating trees by giving each one a completely different random 10% subset of the training rows (no overlap between trees). Using the formula, say what happens to \(\rho\), to \(\sigma^2\), and whether this is a good idea.

1. \(\rho\sigma^2+\frac{1-\rho}{B}\sigma^2 = \sigma^2+0=\sigma^2\). Directly: if every \(f_b\) is the same random variable \(f\), then \(\frac1B\sum_b f_b = f\), whose variance is \(\sigma^2\). Averaging identical things does nothing — which is exactly the failure mode in the quiz.

2. Variance \(\ge 0\) forces \(\rho\sigma^2+\frac{1-\rho}{B}\sigma^2\ge0\), i.e. \(\rho\ge-\frac{1}{B-1}\). At that boundary the variance is exactly zero. This is not an artefact: \(B\) exchangeable variables cannot all be strongly negatively correlated, because their correlation matrix must stay positive semi-definite, and \(-\frac{1}{B-1}\) is precisely where its smallest eigenvalue hits zero. In practice \(\rho>0\) always for bagged trees — they share data.

3. \(\rho\) falls a great deal (disjoint data means the only shared information is the underlying distribution). But each tree now trains on \(n/10\) rows, so its variance \(\sigma^2\) rises sharply and its bias rises too — a tree on 10% of the data is much worse. Total error is \(\text{bias}^2 + \rho\sigma^2 + \frac{1-\rho}{B}\sigma^2\), and the bias term is untouched by averaging. So: usually a bad idea, and it is the same trade-off as \(m\) in a random forest, pushed to an extreme. The code block measures exactly this trade-off for \(m\) and finds the corner solution \(m=d\) on that problem — which is why you tune it rather than trusting a default.

Derive gradient boosting for logistic loss \(L(y,F)=\log\!\big(1+e^{-yF}\big)\) with \(y\in\{-1,+1\}\) and \(F\) the log-odds.

  1. Compute \(g_i=\partial L/\partial F\) and \(h_i=\partial^2 L/\partial F^2\).
  2. Write the Newton leaf value \(w_j^\star\) and interpret \(H_j\).
  3. What is \(F_0\)?
  4. Show that a point the ensemble already classifies confidently and correctly contributes almost nothing to either \(G_j\) or \(H_j\), and say what that means computationally.
  5. Implement it and check that the training logistic loss decreases monotonically for small \(\nu\).

1. Write \(u=-yF\), so \(L=\log(1+e^{u})\) and \(\frac{\partial L}{\partial u}=\frac{e^u}{1+e^u}=\sigma(u)\). By the chain rule \(\frac{\partial u}{\partial F}=-y\), so

\[ g = -y\,\sigma(-yF) = \frac{-y}{1+e^{yF}}. \]

For the second derivative, using \(\sigma'=\sigma(1-\sigma)\) and another factor of \(-y\), with \(y^2=1\):

\[ h = y^2\,\sigma(-yF)\big(1-\sigma(-yF)\big) = \sigma(yF)\big(1-\sigma(yF)\big) = p(1-p), \quad p=\sigma(F). \]

Note \(h\) does not depend on \(y\) — only on how confident the current model is.

2. \(w_j^\star = -\dfrac{\sum_{i\in R_j} g_i}{\sum_{i\in R_j} h_i + \lambda} = \dfrac{\sum_{i\in R_j} y_i\,\sigma(-y_iF_i)}{\sum_{i\in R_j} p_i(1-p_i)+\lambda}\).

The numerator is a sum of signed "how wrong are we" terms; the denominator is the total curvature. Since \(p(1-p)\le\tfrac14\), \(H_j\) is an effective sample size that counts uncertain points fully and confident points barely at all. That is exactly what XGBoost's min_child_weight constrains: not the number of points in a leaf, but the amount of usable information.

3. \(F_0=\argmin_c\sum_i\log(1+e^{-y_ic})\). Differentiating and setting to zero gives \(\sum_i y_i\sigma(-y_ic)=0\), whose solution is \(F_0=\log\frac{n_+}{n_-}\) — the log-odds of the base rate, the same intercept-only fit as in Lecture 5.

4. Confident and correct means \(y_iF_i \gg 0\). Then \(|g_i|=\sigma(-y_iF_i)\approx e^{-y_iF_i}\to0\) and \(h_i=p(1-p)\to0\), both exponentially fast. So such a point contributes essentially nothing to any leaf's \(G\) or \(H\) and cannot influence the next tree. Computationally, that is the licence to ignore it: it justifies gradient-based one-sided sampling (LightGBM's GOSS), which keeps the large-gradient points and subsamples the rest. It is also the precise sense in which boosting "focuses on hard examples" — a consequence of the derivative, not a design choice.

5. Reuse grow and pred: at each round compute g = -y/(1+np.exp(y*F)) and h = p*(1-p), fit a tree to -g/h weighted by h (or simply to -g for the first-order version), recompute the leaf values as \(-G_j/(H_j+\lambda)\), and update \(F \mathrel{+}= \nu\,h_m\). Track np.log1p(np.exp(-y*F)).mean(): it decreases monotonically for \(\nu\) small. For \(\nu=1\) it need not — the Taylor expansion is only local, exactly as in Lecture 3.
